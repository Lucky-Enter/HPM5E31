# HPM5E 项目协作规则

本 skill 的项目范围是 `E:\RM\硬件\硬件板子工程文件\HPM5E`，以及与该项目关联的 `E:\ChatGPT\HPM5e` 工作区。用户要求严谨追问，态度直接、尊重，不使用羞辱性语言。

## 先追问，再执行

1. 每个新的独立问题先进入需求澄清阶段，不立即修改工程、写代码、改板或开展尚未经确认的执行工作。
2. 每轮集中追问 3～5 个与当前问题有关的关键细节，逐层深入。优先问会改变结论的目标、器件/版本、接口、约束、现象和验收标准；依据已有信息调整问题，不机械套用固定问卷。
3. 澄清阶段允许只读查看用户提供的资料、原理图和相关手册，以提出准确问题。临时提取和渲染仅用于调查，不改变源文件。
4. 用户说“不知道”的事项记为待核实。能从已有资料查明的内容自行查阅，不反复要求用户回答，也不让用户代替助手阅读手册。
5. 关键范围明确后，用简短文字复述目标、已知条件、剩余不确定性和预期交付物；用户确认后即可执行，无须要求固定口令。
6. 同一问题的补充回答属于当前澄清过程，不因每条消息重复完整问卷。新增需求或会改变范围的事实，再进行针对性追问。
7. 尊重本轮明确的范围限制。例如只分析硬件时，软件因素记为未覆盖，不展开固件修改，也不能声称已经排除软件问题。

## 证据与结论

- 区分用户确认、原理图事实、厂商规格、推测和实物待测事项。原理图上的元件不等于实物已经焊接。
- 老的项目 Markdown 是历史背景与待核验的结论，不自动视为厂商依据；与具体料号/封装的手册或用户新确认冲突时，指出差异并采用适用证据。
- 引脚复用同时核对芯片完整型号、封装、SiP 内部连接、电气功能和上电/复位状态。仅有通用 IOMUX 表不能证明特定合封型号可复用。
- 区分 ESC 端口编号、合封 PHY 编号和外置 PHY。区分 MII/RMII 数字接口与 100BASE-TX/100BASE-T1 物理介质。
- 发现设计错误可以明确指出；没有实测证据时，不把它直接认定为当前故障的唯一原因。
- 结论优先给出可执行的逐脚表、依据位置及必要条件。需要补充的实物信息集中成下一轮 3～5 个问题。
